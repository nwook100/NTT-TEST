# 하이닉스 시리얼 본호 중복 관리 (구글 시트 버전)

구글 시트를 DB로 쓰는 바코드 등록·중복 차단 웹앱입니다.
**작업자는 바코드만 찍고**, 나머지(설정·점검·파일 관리)는 모두 자동입니다.

## 바코드 형식 (18자리)
```
BX3812  260630  B  02051
고정번호 날짜    구분 본호
(6)     YYMMDD  (1)  (5)
```
- 구분: `A` = 노멀, `B` = 비드
- 본호는 **날짜가 바뀌면 00001부터 다시 시작**하고, **A(노멀)와 B(비드)는 본호를 따로** 매깁니다.
- **중복 판정 = 같은 날짜 + 같은 구분(A/B) 안의 본호**. `BX3812260630B02051` 등록 후:
  - `BX3812260630B02051` → ⛔ **중복**
  - `BX3812260630A02051` → ✅ 정상 (A와 B는 따로)
  - `BX3812260701B02051` → ✅ 정상 (날짜가 다름)
- 자릿수·날짜·구분·고정번호가 틀린 바코드(스캔 오류 등)는 **형식 오류**로 거절합니다.

## 설치 (3단계, 약 3분)
1. 구글 시트 → **확장 프로그램 > Apps Script** → `dist/설치용_Code.gs` 내용을 `Code.gs` 에 전부 붙여넣고 저장
2. **배포 > 새 배포 > 웹 앱** — 실행: **나** / 액세스: **모든 사용자** → 액세스 승인 (**고급 > 이동 > 허용**)
3. 나온 **웹 앱 URL 을 한 번 열기** → "설치가 끝났습니다" 화면에 **작업자용 주소**가 나옵니다. 작업 PC 브라우저에 즐겨찾기하면 끝.

자동으로 되는 것: DB 시트 생성, 작업자/관리자 주소 생성, 매일 새벽 3시 자동 점검 예약.

> 코드를 수정한 뒤에는 **배포 > 배포 관리 > 편집(연필) > 버전: 새 버전** 으로 다시 배포해야 반영됩니다. 주소는 그대로입니다.

## 화면
| 주소 | 누가 | 보이는 것 |
|---|---|---|
| 작업자용 주소 | 작업 PC | **스캔 칸 하나**. 찍으면 즉시 중복 검사 + 기록. 로그인·입력 없음. 작업자 칸에 PC 이름(예: `PC-7F3A`) 자동 기록 |
| 관리자용 주소 | 관리자 | 스캔 + 연속 발번 + 일괄 검사 + 이력 조회 + 관리(작업자 주소 교체, 자동 점검 결과, 저장 파일) |
| 그 외 주소 | - | 접근 안내만 |

## 속도
- 형식 오류·방금 찍은 바코드는 **서버를 기다리지 않고 즉시** 경고음 (최종 판정은 서버)
- 찍은 바코드는 대기열에 쌓였다가 묶어서 한 번에 전송, 통계도 같은 응답으로 받음 (요청 수 최소화)
- 스캔 때 **그 달 시트의 바코드 열 하나만** 읽음 → 전체가 100만 건이어도 속도 동일

## 안정성 · 보안
| 위험 | 대책 |
|---|---|
| 인터넷 끊김 / 서버 일시 오류 / 응답 없음 | 스캔은 계속 가능. **자동 재전송**(1·3·7·15·30초, 이후 1분마다), 응답 없으면 시간 초과 후 재전송. 같은 묶음 번호로 보내 **두 번 등록·가짜 중복 없음** |
| 창이 닫히거나 PC가 꺼짐 | 못 보낸 스캔은 PC에 보관 → 다시 열면 **자동 재전송** |
| DB 시트가 삭제·이름 변경됨 | 중복을 놓치지 않도록 **등록을 멈추고 즉시 빨간 경고**. 복구되면 자동으로 이어서 전송 |
| 연결 상태를 모름 | 화면 오른쪽 위 **● 연결됨 / 연결 불안정** 표시, 1분마다 확인. 화면 꺼짐 방지 |
| 주소가 외부로 샘 | 주소에 추측 불가능한 비밀 키. 관리자 화면에서 **작업자용 주소 바꾸기** 한 번이면 옛 주소 즉시 차단 |
| 작업자가 관리 기능 사용 | 작업자용 주소로는 스캔·통계만 가능 (발번·이력·관리는 관리자 주소 전용) |
| LOT·비고에 `=` 수식 입력 | 글자로 저장, 길이 제한 |
| 누군가 DB 시트를 직접 수정 | DB·로그 시트 **보호** (소유자만 수정) |
| 잘못 읽힌 바코드 | 자릿수·날짜·구분·고정번호 + **날짜 허용 범위**(2년 전 ~ 한 달 뒤) 검사 |
| 여러 PC 동시 등록 | 서버 잠금으로 한 번에 하나씩 처리 |
| 조용히 쌓이는 문제 | **매일 새벽 자동 점검**(중복·형식오류·사라진 시트·통계 재계산) → `자동점검` 시트 기록, 문제 있으면 **소유자에게 메일** |

## 100만 건 이상 대비
| 문제 | 해결 |
|---|---|
| 구글 시트 한 파일은 **1,000만 칸** 한도 | 한 건 9칸, 파일이 **800만 칸**에 가까워지면 `하이닉스 시리얼 DB (2)` 새 파일 **자동 생성** |
| 스캔마다 전체를 읽으면 느려짐 | 바코드 날짜의 **월별 시트**(`DB_2606` …), 스캔 때 그 달 시트만 읽음 |
| 통계 계산이 느려짐 | 총 건수·오늘 등록·최근 10건은 스크립트 속성에 저장 |

모의 환경에서 3년치 999,936건 적재 확인: 파일 2개로 자동 분할, 스캔 한 묶음당 읽는 칸 약 2.8만(그 달 시트만), 통계 0칸.

## 설정 (`Code.gs` 맨 위, 보통은 바꿀 필요 없음)
| 항목 | 기본값 | 설명 |
|---|---|---|
| `ALLOWED_CODES` | `['BX3812']` | 허용 고정번호. 늘어나면 `['BX3812', 'BX4000']` 처럼 추가 |
| `DUP_SCOPE` | `'DATE_TYPE_SERIAL'` | 같은 날짜 + 같은 A/B 안에서 본호 중복 금지 (현재 규칙) |
| `DATE_PAST_DAYS` / `DATE_FUTURE_DAYS` | `730` / `31` | 바코드 날짜 허용 범위. 오래된 재고를 등록해야 하면 늘리세요 |
| `CHECK_HOUR` / `CHECK_MAIL` | `3` / `true` | 자동 점검 시각, 문제 시 메일 여부 |
| `CELL_LIMIT` | `8000000` | 파일 한 개에 쓸 최대 칸 수 |

## 운영 팁
- `DB_2606` 같은 **탭 이름은 바꾸지 마세요.** 바뀌면 등록이 멈춥니다(안전장치). 되돌리면 자동으로 다시 동작합니다.
- 잘못 등록한 번호는 소유자 계정으로 해당 `DB_YYMM` 시트에서 행을 삭제하면 됩니다. 통계는 다음 날 새벽 자동 점검 때 맞춰집니다.
- 주소를 잃어버리면 시트 메뉴 **시리얼 관리 > 작업자용 / 관리자용 주소 보기**.
- 시트 **소유자 계정**의 비밀번호·2단계 인증을 꼭 관리하세요.
