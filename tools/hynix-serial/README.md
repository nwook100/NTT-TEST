# 하이닉스 시리얼 본호 중복 관리 (구글 시트 버전)

구글 시트를 DB로 쓰는 시리얼 등록/중복 차단 웹앱입니다.

## 바코드 형식 (18자리)
```
BX3812  260630  B  02051
고정번호 날짜    구분 본호
(6)     YYMMDD  (1)  (5)
```
- 구분: `A` = 노멀, `B` = 비드
- 본호는 **날짜가 바뀌면 00001부터 다시 시작**하고, **A(노멀)와 B(비드)는 본호를 따로** 매깁니다.
- **중복 판정 = 같은 날짜 + 같은 구분(A/B) 안의 본호**. `BX3812260630B02051` 등록 후:
  - `BX3812260630B02051` → ⛔ **중복** (같은 날짜, 같은 B, 같은 본호)
  - `BX3812260630A02051` → ✅ 정상 (A와 B는 따로)
  - `BX3812260701B02051` → ✅ 정상 (날짜가 다름)
- 자릿수·날짜·구분·고정번호가 틀린 바코드(스캔 오류 등)는 **형식 오류**로 거절합니다.

여러 PC·작업자가 같은 시트를 공유하며, 동시에 같은 번호를 등록해도 **한 건만** 들어갑니다(서버 잠금).

## 기능
| 탭 | 설명 |
|---|---|
| 등록 / 검사 | **연속 스캔**: 스캐너로 계속 찍기만 하면 찍는 즉시 중복 검사 + 기록. 서버 처리 중에 찍은 것도 대기열에 쌓였다가 한 번에 처리돼 누락 없음. 중복·형식오류면 화면이 빨갛게 번쩍이고 경고음, [이번 스캔 기록] 표에 건별 결과(등록/중복/형식오류) 표시. 전송 실패 시 [실패 항목 다시 보내기] |
| 연속 발번 | 고정번호·날짜·A/B 선택 → **그 날짜·구분의 마지막 본호 다음부터** N개 발번 (새 날짜는 00001부터). 이미 쓴 본호는 건너뜀 |
| 일괄 검사 | 엑셀에서 복사한 목록 붙여넣기 → 신규 / 기존 중복 / 목록 안 중복 / 형식 오류 판정, 신규만 등록 |
| 이력 조회 | 바코드·본호·LOT·작업자로 검색 |

- 상단에 **가장 최근 등록한 날짜·구분의 마지막 본호**가 표시됩니다.
- 시트에 직접 입력해서 생긴 중복·형식오류는 시트 메뉴 **[시리얼 관리 > 시트 내 중복 검사]** 로 찾을 수 있습니다.
- 막힌 시도(중복·형식오류)는 **로그_YYMM** 시트(시도한 달)에 사유와 함께 남습니다.

## 안정성 · 보안
| 위험 | 대책 |
|---|---|
| 웹앱 주소가 새면 아무나 등록·조회 | **작업자 PIN 로그인** 필수. PIN 은 시트 메뉴에서만 등록(시트 편집자만), 해시로만 저장, 10회 틀리면 10분 잠금, 6시간 미사용 시 자동 로그아웃 |
| 작업자 이름 위조 | 등록 기록의 작업자 = 로그인한 PIN 의 이름 (직접 입력 불가) |
| LOT·비고에 `=` 수식 입력 → 시트에서 실행 | `= + - @` 로 시작하면 글자로 저장, 길이 제한 |
| 관리 기능을 웹에서 호출 | 중복 검사·통계 재계산·작업자 관리·파일 목록은 **시트 메뉴에서만** 실행 |
| 누군가 DB 시트를 직접 수정/삭제 | DB·로그 시트 **보호**(소유자만 수정). 시트가 없어지면 **등록을 멈추고** 오류 표시 (중복을 놓친 채 등록되는 일 방지) |
| 잘못 읽힌 바코드 | 자릿수·날짜·구분·고정번호 검사 + **날짜 허용 범위**(2년 전 ~ 한 달 뒤) |
| 인터넷 끊김 / 서버 일시 오류 | 스캔은 계속 가능, **자동 재전송**(2·5·10·20초). 같은 묶음 번호로 보내 **두 번 등록·가짜 중복 없음** |
| 창이 닫히거나 PC가 꺼짐 | 못 보낸 스캔은 PC에 보관 → 다시 열면 **자동 재전송** |
| 로그인 창에 바코드를 찍음 | PIN 으로 보내지 않고 스캔으로 보관, 로그인 후 처리 |
| 구글 일일 사용량 한도 | 스크립트 속성은 요청당 1번 읽고 1번 씀 |
| 여러 PC 동시 등록 | 서버 잠금으로 한 번에 하나씩 처리 |

## 100만 건 이상 대비 구조
| 문제 | 해결 |
|---|---|
| 구글 시트 한 파일은 **1,000만 칸** 한도 | 한 건 9칸으로 줄이고, 파일이 **800만 칸**에 가까워지면 `하이닉스 시리얼 DB (2)` 새 파일을 **자동 생성**해 이어서 기록 |
| 스캔마다 전체를 읽으면 점점 느려짐 | 바코드 날짜의 **월별 시트**(`DB_2606`, `DB_2607` …)에 저장. 중복은 같은 날짜 안에서만 생기므로 스캔 때 **그 달 시트의 바코드 열 하나만** 읽음 |
| 첫 화면 통계 계산이 느려짐 | 총 건수·오늘 등록·최근 10건은 스크립트 속성에 따로 적어 두어 시트를 읽지 않음 |
| 시트 전체 조건부 서식(중복 빨간색) 계산이 느려짐 | 제거하고 메뉴의 **시트 내 중복 검사**로 대체 |

모의 환경에서 3년치 **999,936건**을 적재해 확인한 결과: 파일 2개로 자동 분할(각 1,000만 칸 미만), 스캔 1건당 읽는 칸 약 2.8만(그 달 시트만), 첫 화면 통계 0칸.
한 달에 수십만 건씩 쌓이는 경우에만 스캔이 느려질 수 있습니다(그 달 건수에 비례).

시트 메뉴 **[시리얼 관리]**
- 시트 내 중복 검사 / 통계 다시 계산 (시트를 직접 고친 뒤) / 저장 파일 목록

## 설정 (`Code.gs` 맨 위)
| 항목 | 기본값 | 설명 |
|---|---|---|
| `ALLOWED_CODES` | `['BX3812']` | 허용 고정번호. 다른 고정번호가 생기면 `['BX3812', 'BX4000']` 처럼 추가 |
| `DUP_SCOPE` | `'DATE_TYPE_SERIAL'` | `DATE_TYPE_SERIAL`: 같은 날짜 + 같은 A/B 안에서 본호 중복 금지 (현재 규칙) / `DATE_SERIAL`: A/B가 번호를 같이 쓰는 경우 |
| `CELL_LIMIT` | `8000000` | 파일 한 개에 쓸 최대 칸 수. 넘으면 새 파일 자동 생성 |
| `DATE_PAST_DAYS` / `DATE_FUTURE_DAYS` | `730` / `31` | 바코드 날짜 허용 범위(오늘 기준). 오래된 재고를 등록해야 하면 늘리세요 |
| `SESSION_SEC` | `21600` (6시간) | 마지막 사용 후 로그인 유지 시간 |

## 설치 (약 3분, 파일 1개)
1. 구글 시트를 하나 만들고 **확장 프로그램 > Apps Script** 열기
2. `dist/설치용_Code.gs` 내용을 `Code.gs` 에 전부 붙여넣고 저장 (화면 코드가 이 파일 안에 들어 있어 HTML 파일을 따로 만들 필요 없음)
3. 시트 탭으로 돌아가 **새로고침(F5)** → 상단 메뉴 **시리얼 관리 > 작업자 추가 / PIN 변경** → 이름, PIN(6~12자리) 입력
   (처음 한 번 권한 승인 창: **고급 > 이동 > 허용**). 작업자 수만큼 반복
4. **배포 > 새 배포 > 웹 앱** — 실행 사용자: **나** / 액세스: **Google 계정이 있는 모든 사용자**
5. 나온 **웹 앱 URL** 을 작업 PC에 즐겨찾기 → PIN 으로 로그인 → 스캔. 첫 스캔 때 `DB_YYMM` 시트가 자동으로 만들어집니다.

> 코드를 수정한 뒤에는 **배포 > 배포 관리 > 편집(연필) > 버전: 새 버전** 으로 다시 배포해야 반영됩니다. URL은 그대로입니다.

### 개발용 (코드 수정 시)
- 원본은 `Code.gs`(서버) + `Index.html`(화면) 입니다. 고친 뒤 `node build.mjs` 로 `dist/설치용_Code.gs` 를 다시 만드세요.

## 운영 팁
- 잘못 등록한 번호는 해당 `DB_YYMM` 시트에서 그 행을 삭제하면 다시 쓸 수 있습니다. 삭제 후 메뉴 **통계 다시 계산**을 누르면 총 건수가 맞춰집니다.
- 시트 탭 이름(`DB_2606` 등)은 바꾸지 마세요. 프로그램이 이름으로 시트를 찾습니다.
- 시트 공유는 **보기 권한**만 주고, 등록은 웹앱으로만 하면 실수로 지워지는 일을 막을 수 있습니다.
  (웹앱은 "실행 사용자: 나" 권한으로 기록하므로 작업자에게 편집 권한이 없어도 됩니다)
- 구글 시트 파일 > 버전 기록으로 언제든 이전 상태를 복원할 수 있습니다.
