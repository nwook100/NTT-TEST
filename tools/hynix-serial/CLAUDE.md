# 하이닉스 시리얼 본호 관리 - 업무 규칙 (변경 시 반드시 지킬 것)

## 바코드 형식 (18자리)
`BX3812` `260630` `B` `02051` = 고정번호(6) + 날짜 YYMMDD(6) + 구분(1) + 본호(5)
- 고정번호: 현재 `BX3812` (추가 시 `Code.gs` 의 `ALLOWED_CODES`)
- 구분: `A` = 노멀, `B` = 비드

## 본호 규칙 (사용자 확인 완료)
- 날짜가 바뀌면 본호는 00001부터 다시 시작한다. 99999까지 가는 일은 없다.
- A(노멀)와 B(비드)는 본호를 **따로** 매긴다.
- 따라서 중복 판정 단위 = **고정번호 + 날짜 + 구분(A/B) + 본호** (`DUP_SCOPE = 'DATE_TYPE_SERIAL'`)
  - 0630 B02051 등록 후: 0630 B02051 → 중복 / 0630 A02051 → 정상 / 0701 B02051 → 정상

## 구조
- 구글 시트가 DB, Apps Script 웹앱(`Code.gs` + `Index.html`, 설치용은 `node build.mjs` → `dist/설치용_Code.gs`)
- **100만 건 이상 대비 (사용자 요구사항)**: 스캔 속도가 전체 건수와 무관해야 함
  - 바코드 날짜의 월별 시트 `DB_YYMM` 에 저장, 중복 검사는 그 달 시트의 A열만 읽음 (전체 스캔 금지)
  - 파일당 800만 칸(`CELL_LIMIT`) 넘으면 새 스프레드시트 자동 생성. 월별 시트 위치는 스크립트 속성 `part:YYMM`
  - 통계(total, day:날짜, blk:날짜, recent)는 스크립트 속성에 저장 — 대시보드에서 시트 읽기 금지
  - 시트 전체에 걸린 조건부 서식/수식 금지 (대량 데이터에서 느려짐)
- 등록은 반드시 `LockService` 잠금 안에서 처리 (여러 PC 동시 등록 대비)
- **자동화 (사용자 요구사항: 어렵게 가면 안 됨)**: 작업자는 바코드만 찍는다. 로그인·PIN·입력칸·메뉴 조작을 추가하지 말 것
  - 설치 = 코드 붙여넣기 → 웹앱 배포(액세스: 모든 사용자) → 웹앱 한 번 열기. 첫 방문 때 `claim_()` 이 키 생성·자동 점검 예약
  - 접근은 주소의 비밀 키(`?k=`): 작업자 키(스캔·통계만) / 관리자 키(전체). 작업자 칸 = PC 이름 자동(localStorage)
  - 매일 `nightlyCheck`(트리거 uid 확인) → `check_()` 로 중복·형식오류·사라진 시트·통계 재계산, 문제 시 소유자 메일
- **안정성·보안 (사용자 요구사항: 제품 안전 관련이므로 유지)**
  - 웹에서 호출되는 함수는 모두 `api_(key, fn, adminOnly)` 로 감쌈. 시트 메뉴 기능은 `requireUi_()`
  - 시트에 쓰는 글은 `safeText_` (수식 주입 방지·길이 제한)
  - DB 시트가 없으면 `requireSheet_` 로 등록 중지 (fail-closed). 화면은 즉시 빨간 경고 후 백그라운드 재시도
  - 커밋 요청은 `batchId` 로 멱등 처리 (`idempotent_`), 화면은 같은 batchId 로 자동 재전송 + 호출 시간 초과
  - 스크립트 속성은 `pget_/pset_/pflush_` 캐시로만 접근 (일일 사용량 한도)
  - 문자열 `replace` 에 사용자/설정 값을 넣을 때는 함수 형태로 (`$` 특수문자 문제)
- 사용자는 개발자가 아닌 영업 담당자: 화면 문구와 안내는 한국어로 쉽게
