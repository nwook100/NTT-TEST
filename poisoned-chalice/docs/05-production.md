## 0. 전제: 우리 팀의 현실

| 항목 | 내용 |
|---|---|
| 개발자 | 1인. 경기도 안산 반도체 부품 제조사 영업 과장(81년생), 개발은 배우는 중 |
| 작업 가능 시간 | **주 8~10시간**을 기본으로 잡는다: 평일 저녁 2회 × 1.5시간 + 주말 하루 5~6시간 |
| 변수 | 월말·분기말 영업 마감, 고객사 출장, 연말 송년회, 설 연휴, 가족 행사 → **한 달에 1주는 작업 0시간**으로 가정 |
| 원칙 | ① 기능을 늘리기보다 "끝까지 출시"를 우선한다 ② 서버 없음, 로그인 없음, 결제 없음 (v1.0 기준) ③ 매주 "브라우저에서 한 판 끝까지 돌아가는 상태"를 유지한다 |

이 계획서의 모든 기간은 위 시간을 기준으로 잡았다. 주 20시간 이상 쓸 수 있는 주가 생기면 앞당기면 되고, 일정이 밀리면 기능을 덜어낸다. 출시일은 미루지 않는 쪽을 택한다.

## 1. 기술 스택 결정

### 1-1. 결정
**HTML5 + 바닐라 JavaScript(단일 페이지) → Capacitor로 iOS/Android 앱 패키징**

```
poisoned-chalice/
├─ www/                ← 게임 본체 (index.html, events-extra.js, css, 이미지)
├─ android/            ← npx cap add android 로 생성 (Android Studio 프로젝트)
├─ ios/                ← npx cap add ios 로 생성 (Xcode 프로젝트)
├─ capacitor.config.json
└─ package.json
```

### 1-2. 이유
1. **게임의 성격과 잘 맞는다.** 텍스트·버튼·게이지 위주의 턴제 경영 시뮬이다. 물리 엔진, 3D, 60fps 액션이 필요 없다. 스코어보드 UI는 HTML/CSS로 가장 쉽게 만들 수 있다.
2. **배우기 쉽다.** 필요한 도구가 브라우저 하나와 메모장 수준의 에디터(VS Code)뿐이다. 수정하고 F5를 누르면 결과가 바로 보이므로 초보자가 배우기 좋다.
3. **코드 하나로 세 곳에 낸다.** 웹(지인 테스트 링크), Android, iOS 모두 같은 `www/` 폴더를 쓴다.
4. **회사 PC·집 PC·노트북 어디서든 작업할 수 있다.** 무거운 엔진을 설치하지 않아도 된다(앱 빌드 단계만 Android Studio/Xcode가 필요하다).
5. **잃을 것이 적다.** 나중에 Unity 등으로 옮기더라도 기획·밸런스·이벤트 텍스트(데이터)는 그대로 가져갈 수 있다.

### 1-3. 대안 비교

| 항목 | **HTML5 + Capacitor (채택)** | Unity | Flutter | React Native |
|---|---|---|---|---|
| 언어 | JavaScript, HTML, CSS | C# | Dart | JavaScript/TypeScript + React |
| 초보 학습 난이도 | ★☆☆ 가장 쉬움 | ★★★ 에디터·컴포넌트 개념이 많음 | ★★☆ Dart와 위젯 트리를 새로 배워야 함 | ★★☆ React 개념(상태, 훅)이 먼저 필요 |
| 텍스트/UI 중심 게임 적합도 | 매우 좋음 | 보통 (UI 작업이 오히려 번거로움) | 좋음 | 좋음 |
| 액션·그래픽 게임 적합도 | 낮음 | 매우 좋음 | 낮음~보통 | 낮음 |
| 수정 후 확인 속도 | 브라우저 새로고침 (즉시) | 에디터 Play (수 초) | Hot reload (빠름) | Fast refresh (빠름) |
| 웹 버전 동시 배포 | 기본 지원 | WebGL 빌드 (무겁다) | 가능 (다소 무거움) | 별도 작업 필요 |
| 설치 용량·PC 사양 | 가벼움 | 무거움 (수십 GB) | 중간 | 중간 |
| iOS 빌드에 Mac 필요 | 필요 | 필요 | 필요 | 필요 |
| 비용 | 무료 | 개인은 매출 기준 이하 무료 (Personal 조건은 **확인 필요**) | 무료 | 무료 |
| 성능 | WebView 한계가 있으나 이 게임 규모라면 충분 | 최상 | 우수 | 우수 |
| 스토어 심사 리스크 | "웹사이트를 앱으로 감쌌을 뿐"으로 보이면 거절될 수 있음 (리스크 4 참고) | 낮음 | 낮음 | 낮음 |
| 결론 | **이 프로젝트의 최적안** | 다음 작품이 그래픽 게임이면 검토 | 앱 개발 커리어가 목표라면 검토 | 웹 프론트 경험이 있다면 검토 |

> 어느 대안을 고르든 iOS 앱을 내려면 Mac과 Xcode를 거쳐야 한다. 스택을 바꾼다고 이 문제가 사라지지 않는다.

### 3-2. Mac 필요 여부 (iOS)

- 선택지:

| 방법 | 비용(대략) | 장점 | 단점 |
|---|---|---|---|
| 중고 Mac mini (Apple Silicon M1 이상) | 60~90만 원 (**시세 확인 필요**) | 시뮬레이터, 디버깅, 빌드를 모두 직접 할 수 있다. 가장 덜 답답하다 | 초기 비용. 최신 Xcode가 요구하는 macOS 버전을 지원하는 모델인지 확인 필요 |
| 클라우드 Mac 대여 (MacinCloud 등) | 월 수만 원 수준 (**확인 필요**) | 필요한 달만 쓴다 | 원격 화면이 느리다. 실기기 연결이 어렵다 |
| 클라우드 빌드 CI (Codemagic, GitHub Actions macOS 러너, Ionic Appflow 등) | 무료 할당량이 있는 곳이 있다 (**요금·서비스 지속 여부 확인 필요**) | Mac 없이 빌드·TestFlight 업로드까지 자동화할 수 있다 | 서명 인증서·프로비저닝 설정이 초보자에게 어렵다. 오류가 나면 원인 찾기가 힘들다 |

### 3-4. 연령등급
- [ ] **Google Play**: Play Console의 콘텐츠 등급 설문(IARC)을 작성하면 국가별 등급이 자동으로 부여된다
- [ ] **App Store**: App Store Connect의 연령 등급 설문을 작성한다
- [ ] 예상 등급: 폭력·선정성 없음. 다만 블랙코미디의 언어 표현(욕설 수위), 음주(치맥) 묘사, 사행성(도박성 요소 없음)에 따라 **전체이용가 또는 12세**가 나올 것으로 본다
- [ ] **도박·확률형 아이템 요소를 넣지 않는다**(국내 사행성 심사 리스크를 피하기 위해)

### 3-5. 국내 게임물관리위원회(게임위) 자체등급분류 관련
- 일반적인 구조: Google Play와 App Store 같은 오픈마켓은 **자체등급분류사업자**로 지정되어 있다. 따라서 스토어 설문으로 받은 등급이 국내 등급으로 인정되고, 게임위는 사후관리를 맡는다. 즉 **스토어로만 유통하면 게임위에 따로 등급을 신청할 필요가 없는 것이 일반적**이다.
- **확인 필요 사항**
  - [ ] Apple App Store가 현재도 자체등급분류사업자로 지정되어 있는지(게임위 홈페이지의 지정 사업자 목록)
  - [ ] **웹 버전(itch.io, 개인 홈페이지, 토스 앱인토스 등)을 별도로 공개하면** 스토어 등급과 별개로 등급분류를 받거나 게임물 정보를 제출해야 할 수 있다. 미제출 시 등급미필 게임물로 간주될 수 있다는 안내가 있다 → 지인 테스트용 웹 링크는 **비공개(링크 공유 한정)**로 운영하고, 공개 웹 배포는 게임위에 먼저 확인한다
  - [ ] 무료 게임을 개인이 배포할 때 사업자등록이나 게임 관련 신고 의무가 있는지
  - [ ] 해외 앱마켓의 게임물 내용정보 제공 의무화 등 관련 법 개정 진행 상황
- 문의처: 게임물관리위원회 홈페이지 및 고객센터(공식 채널에서 최신 정보 확인)

## 4. Capacitor 빌드 단계별 명령어

> 기준: Capacitor 8 (Node.js 22 이상, Android Studio Otter 2025.2.1 이상, Xcode 26 이상). Capacitor 9 정식판이 나왔다면 요구사항이 올라간다(Xcode 27, iOS 16 이상 등). 시작 전에 **공식 문서에서 최신 버전 확인 필요**.

### 4-0. 사전 설치
1. **Node.js LTS(22 이상)**: nodejs.org에서 설치 → 터미널에서 `node -v`로 확인
2. **VS Code**
3. **Android Studio**: 설치 후 SDK Manager에서 Android SDK를 받는다
4. (iOS) **Mac + Xcode**: App Store에서 설치한 뒤 `xcode-select --install` 실행

### 4-1. 프로젝트 초기화 (한 번만)
```bash
cd poisoned-chalice

# package.json 생성
npm init -y

# Capacitor 설치
npm install @capacitor/core
npm install -D @capacitor/cli

# Capacitor 초기화: 앱 이름, 앱 ID(번들ID), 웹 폴더 지정
npx cap init "Poisoned Chalice" com.yourname.poisonedchalice --web-dir www
```
- 앱 ID는 스토어에 올린 뒤에는 바꿀 수 없다. 신중하게 정한다.
- 홈 화면에 표시될 한글 이름 "독이 든 성배"는 생성된 프로젝트에서 따로 설정한다(Android `res/values/strings.xml`의 `app_name`, iOS `Info.plist`의 `CFBundleDisplayName`).

### 4-2. 플랫폼 추가 (한 번만)
```bash
npm install @capacitor/android @capacitor/ios

npx cap add android     # android/ 폴더 생성
npx cap add ios         # ios/ 폴더 생성 (Mac에서만 의미 있음)
```

### 4-3. 매번 하는 작업: 웹 코드 수정 → 앱에 반영
```bash
# www/ 를 수정한 다음
npx cap sync            # www 내용과 플러그인을 android/ios 프로젝트에 복사
```

### 4-4. 실행
```bash
# Android
npx cap open android    # Android Studio가 열림 → 상단 ▶(Run) 버튼, 에뮬레이터 또는 USB 연결 폰 선택
# 또는
npx cap run android     # 터미널에서 기기를 골라 바로 실행

# iOS (Mac)
npx cap open ios        # Xcode가 열림 → Signing & Capabilities에서 Team 선택 → ▶ 실행
# 또는
npx cap run ios
```
- Android 폰: 설정 → 휴대전화 정보 → 빌드번호 7번 탭 → 개발자 옵션 → USB 디버깅 켜기
- iPhone: Xcode에서 처음 실행한 뒤 iPhone 설정 → 일반 → VPN 및 기기 관리에서 개발자를 신뢰해야 한다

### 4-5. 아이콘·스플래시 자동 생성
```bash
npm install -D @capacitor/assets
# assets/icon.png (1024x1024), assets/splash.png (2732x2732) 준비 후
npx capacitor-assets generate
```

### 4-6. 스토어 업로드용 빌드
- **Android**: Android Studio → Build → Generate Signed Bundle / APK → **Android App Bundle(.aab)** → 키스토어 생성·선택 → release → Play Console 비공개 테스트 트랙에 업로드
- **iOS**: Xcode → 상단 기기를 "Any iOS Device"로 선택 → Product → Archive → Distribute App → App Store Connect → 업로드한 뒤 TestFlight에서 확인
- 업데이트할 때마다 **버전 번호를 올린다**: Android `versionCode`(정수, 매번 +1)와 `versionName`, iOS Version과 Build

### 4-7. 추천 플러그인 (필요할 때만)
| 플러그인 | 용도 |
|---|---|
| `@capacitor/app` | Android 뒤로가기 버튼, 앱 백그라운드/복귀 이벤트 |
| `@capacitor/preferences` | localStorage보다 안정적인 기기 저장 |
| `@capacitor/haptics` | 진동 피드백 |
| `@capacitor/status-bar`, `@capacitor/splash-screen` | 상단바 색, 스플래시 제어 |

- 영업 보고서처럼 **"변경 전 / 변경 후 / 결과"를 한 줄씩 메모**하면 실력이 빨리 는다.
- 모르는 코드는 한 줄씩 AI에게 "이 줄이 무슨 뜻이야?"라고 묻는다. 고치는 것도 AI에게 맡길 수 있지만, **이해한 다음에 붙여넣는다.**
- 한 번에 한 가지만 바꾸고 바로 새로고침해서 확인한다.
