## 2. 버그

### B-1 [치명] 안내 오버레이가 `hidden`이어도 계속 표시되어 실제 입력이 전부 막힘

- 증상: "단속 시작"을 누르면 타이머·스폰은 돌아가지만, 안내 패널(개막 30분 전…)이 잔디밭 위에 그대로 남는다. 파란 돗자리를 마우스로 클릭하거나 손가락으로 탭해도 점수가 0에서 변하지 않는다. (`phone-02-playing.png`, `desktop-02-playing.png` 참고 — HUD는 돌아가는데 오버레이가 떠 있음)
- 원인: `.overlay { display: grid; }`(작성자 스타일)가 UA 스타일 `[hidden] { display: none }`을 덮어쓴다. `overlay.hidden = true`는 속성만 바뀌고 계산된 `display`는 `grid` 그대로.
- 재현(Playwright 측정값):
  1. 페이지 열기 → `#start` 클릭
  2. `getComputedStyle(#overlay).display` → `"grid"`, `overlay.hidden` → `true`
  3. 파란 돗자리 셀 중앙 좌표에서 `document.elementFromPoint()` → `#overlay`
  4. `page.mouse.click(셀 중앙)` / `page.touchscreen.tap(셀 중앙)` → 점수 0 → 0 (반응 없음)
  5. 반면 셀에 `dispatchEvent(pointerdown)`을 직접 쏘면 점수가 오른다 → 로직은 정상, 입력이 오버레이에 흡수되는 것.
- 영향: 사실상 게임 플레이 불가. 아무것도 못 누르니 약 15초 뒤 "민원 폭발…"로 끝난다.
- 수정 제안: `.overlay[hidden] { display: none; }` 한 줄 추가(가장 안전), 또는 `overlay.style.display = "none"/""`로 직접 토글.

### B-2 [중] 오인 단속으로 민원 게이지가 100%가 돼도 게임이 끝나지 않음

- 증상: 안내문은 "잘못 누르면 민원이 폭발합니다"인데, 노란 돗자리를 아무리 눌러도 게이지만 100%에서 꽉 찬 채 게임이 계속된다.
- 원인: `hit()`에서 `anger = min(100, anger+15)`로 100에 고정된 뒤, `loop()`가 종료 판정 전에 `anger += hogs*dt*(…) - dt*1.5`를 먼저 적용한다. 보드에 파란 돗자리가 0~1개면 감소 항이 더 커서 99.98 → `>= 100` 조건을 영원히 못 만족.
- 재현(fake clock):
  1. 시작 → 파란 4개 모두 제거(hogs = 0)
  2. 노란 돗자리 7회 이상 pointerdown → 게이지 100%, `over: false`
  3. 1프레임 뒤 99.976%, 1초 뒤 98.46%, 게임 계속 진행
- 수정 제안: `hit()`의 family 분기 끝에서 `if (state.anger >= 100) return end(false)`, 또는 루프의 종료 판정을 게이지 갱신 전에 수행. 아울러 15 가산 후 clamp 하지 말고 100 이상이면 즉시 종료.

### B-3 [경미] "대기 N명"이 게임플레이에 영향이 없음

- `state.queue`는 2초마다 +1(최대 30), 파란 돗자리를 걷어낼 때 -1 하며 그 자리에 관람객을 앉힐 뿐, 민원 게이지나 점수에 전혀 관여하지 않는다. "관람객 민원 게이지" 라벨 바로 옆에 있어 연관된 수치처럼 읽히지만 장식이다.
- 제안: 대기 인원만큼 게이지 상승 속도를 올리거나(예: `+ queue*0.05*dt`), 대기 인원이 많을 때 걷어내면 보너스를 주는 식으로 의미를 부여.

### B-4 [경미] 콤보가 시간으로 감소하지 않아 4회 클릭 후 x5 영구 고정

- 콤보는 오인 단속에서만 리셋된다. 3초간 아무것도 안 해도 유지되므로 "콤보"라기보다 "실수 안 함 보너스"이고, 점수는 사실상 `500 × 걷어낸 개수`가 된다.
- 제안: 마지막 성공 후 2~3초 지나면 한 단계씩 감소.

### B-5 [경미] 1280×800에서 격자 하단과 범례가 폴드 아래

- 문서 높이 1016px. `.wrap` max-width 560px라 셀이 128px로 커지고 5행 격자가 길어진다. 플레이 중 스크롤이 필요하다.
- 제안: 데스크톱에서 격자 높이를 `min(100vh - HUD, …)`로 제한하거나 `.wrap` max-width를 480px 정도로 줄이기, 또는 짧은 뷰포트에서 헤더 문구를 접기.

### B-6 [경미] 선점 돗자리 "맡아둔 자리" 태그가 셀 밖으로 넘치고 너무 작음

- `.tag`가 `top: -8px`라 셀 상단보다 5px 위로 나가고(390px 폰 기준 셀 74.5px), 글자 10px라 거의 못 읽는다. 위 행 셀의 하단과 겹쳐 보인다.
- 제안: 태그를 돗자리 안쪽 상단(`top: 4px`)에 두고 11~12px로.

### B-7 [경미] 오버레이 문장이 한글 단어 중간에서 줄바꿈

- 예: "운영본부로 몰려갔어 / 요." (`desktop-03-end.png`). `.overlay p { max-width: 32ch }`에 `word-break: keep-all` 미지정.

### B-8 [경미, 코드 리뷰] 걷어낸 직후 350ms 동안 그 셀이 스폰 대상이 됨

- `hit()`이 `c.kind = null`로 바꾸고 350ms 뒤 관람객을 앉히는데, 그 사이 `loop()`의 `place()`가 같은 셀을 빈칸으로 보고 새 돗자리를 즉시 그릴 수 있다. 사라지는 애니메이션 중 새 파란 돗자리가 튀어나오면 손가락이 아직 그 위에 있어 의도치 않은 연타·오인이 날 수 있다.
- 제안: `cleared` 상태 플래그를 두고 스폰 후보에서 제외.

### 참고(버그 아님)

- 모바일에서 `touch-action`이 없다. 빠른 연타 시 브라우저 더블탭 줌이 끼어들 수 있어 `.cell { touch-action: manipulation; }` 권장(에뮬레이션에서는 재현 안 됨).
- 이모지는 OS 이모지 폰트에 의존한다. 테스트 환경에는 컬러 이모지 폰트가 없어 네모로 보였는데, 돗자리 색(파랑/노랑)만으로도 구분은 되므로 치명적이진 않다.
- Google Fonts는 외부 네트워크 의존. 차단 시 시스템 고딕으로 폴백되며 레이아웃은 깨지지 않음.

## 4. 밸런스 의견

플레이어 속도별 시뮬레이션(fake clock, 파란 돗자리 하나씩 R ms 간격으로 제거, M = 오인 확률):

| 반응 속도 R | 오인 M | 결과 |
|---|---|---|
| 0.7초 | 0 | 완주, 30,000점 |
| 1.0초 | 0 | 완주, 29,500점 |
| 1.5초 | 0 | 58초에 민원 폭발, 18,500점 |
| 2.0초 | 0 | 78초에 민원 폭발, 18,500점 |
| 0.7초 | 10% | 완주, 23,200점 |
| 1.0초 | 15% | 79초에 민원 폭발, 9,400점 |

- **너무 쉽다.** 파랑/노랑 색만 구분하면 되고, 초당 1번만 눌러도 끝까지 살아남는다. 스폰 간격이 1.3초 → 0.55초로 줄고 파란 비율이 55→70%라 후반 파란 유입이 초당 1.27개까지 오르지만, 사람 손은 초당 2~3번은 쉽게 누른다. 지는 길은 사실상 "손을 떼는 것"뿐.
- **초반 게이지는 오히려 급하다.** 시작 시 파란 4개가 깔려 있어 가만히 있으면 2.9%/초로 오르고 15초면 끝난다. 반면 손만 움직이면 게이지는 거의 0에 머문다(완주 시 평균 0~5%). 중간 긴장감이 없다.
- **칭호 기준이 낮다.** 완주하면 거의 무조건 15,000점 이상 → "축제의 전설". 1초/클릭 완주가 28,500점이므로 전설 기준은 25,000~30,000, 반장 15,000, 안전요원 7,000 정도가 맞다. 콤보 감쇠(B-4)를 넣으면 기준을 다시 잡아야 한다.
- **90초는 약간 길다.** 난이도 곡선이 평탄해 40초부터는 같은 동작의 반복이다. 60초로 줄이거나, 90초를 유지하려면 후반 변주가 필요하다. 아이디어:
  - 노란 돗자리에 짐만 남기고 사람이 잠깐 자리를 비우는 "속임수" 돗자리(걷어내면 감점) — 색이 아닌 내용을 봐야 하게.
  - 파란 돗자리에 유효 시간(계속 두면 게이지 급증)을 주어 우선순위 판단 유도.
  - 대기 인원(B-3)을 게이지 상승 계수로 연결해 후반 압박.
  - 콤보 감쇠로 빠른 손에 보상.

## 5. 우선순위 제안

1. B-1 오버레이 `display` 수정 — 이게 없으면 출시 불가.
2. B-2 오인 단속 100% 종료 판정.
3. 칭호 기준 상향 + 콤보 감쇠(B-4) + 대기 인원 연동(B-3)으로 난이도 재조정, 길이 60초 검토.
4. 데스크톱 폴드(B-5), 태그 가독성(B-6), keep-all(B-7), touch-action.
